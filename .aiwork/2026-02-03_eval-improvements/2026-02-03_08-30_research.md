# Eval Process Improvements

## Current State

- 31 evals × 2-3 variants × 2 trials = ~186 generations per run
- 299 MB results (1 eval bloated with node_modules)
- Sequential processing, no caching
- AI judge spawns separate process per check

## Token Efficiency

### 1. Drop baseline when rule is "already-known"

Once classified, skip baseline generation on subsequent runs. Store classification in `eval-cache.json`.

### 3. Reduce trial count selectively

- "already-known" rules: 1 trial
- Stable rules (pass rate >90%): 1 trial
- Flaky rules: keep 2 trials

### 4. Batch AI judge checks

Combine all criteria into single prompt:

```
Evaluate against these criteria:
1. <criteria-a> → PASS/FAIL
2. <criteria-b> → PASS/FAIL
```

## Speed

### 5. Parallel generation

`Promise.all()` with concurrency limit (e.g., 3-5 concurrent evals). Already isolated environments support this.

## Storage

### 8. Filter node_modules

Add to runner.mjs:

```js
// Skip copying node_modules, .git, dist
const SKIP_DIRS = ["node_modules", ".git", "dist", ".nuxt"]
```

also skip package-lock.json and pnpm-lock.yaml

### 9. Dedupe setup.md

Store once per eval, not per trial.

## Quality

### 11. Smarter regex patterns

Some patterns too rigid. Example: checking exact spacing in template directives.

### 12. Add negative cases

Ensure rules don't over-trigger. Add prompts where rule should NOT apply, verify no pattern.

### 13. Track flakiness

Log pass/fail per trial, flag rules with >20% variance across trials.
